Y 12 · DIAMOND LEVEL

Mod changes are tested before they go live.

Installs and updates run on a copy of your server first. A change reaches the live server and your friends' pack only when it passes, or when you approve one that couldn't be fully tested. Each change shows its results, and you can undo the last five.

  1. ✓Planfewest changes
  2. ✓Server booton a copy
  3. ✓Client joinreal client
  4. !Your approvalwhen it's unclear
  5. ✓Restartwhen it's empty
  6. ✓Friends syncedexact pack

  1. The server dry-boots it

    Before anything boots, a solver checks the whole pack: dependencies, versions and Java. Then the server's own loader boots it in a sandbox (Fabric, Forge, NeoForge). A missing library or the wrong Java gets repaired and tested again. A change that fails never touches your live mods.

  2. A real client boots it

    On servers that sync mods to friends with AutoModpack, a real Minecraft client launches the pack your friends would get (Fabric, Forge and NeoForge, Minecraft 1.20 and newer), so client crashes show up before anyone downloads anything.

  3. Then it joins

    The panel boots a throwaway server with the same mods and a fresh world, and the test client joins it for real, because some mods only break at the moment a player connects.

  4. Unclear means you decide

    Each change shows passed, failed or not tested, with the loader's own error lines. A change that couldn't be fully tested waits for you: apply it anyway, test again, or discard it. Undo last change puts back what it replaced.

Friends never manage pack files either: AutoModpack syncs the tested pack into their game when they join. The tests run on your machine's graphics, so they can't vouch for every friend's GPU or shaders.
